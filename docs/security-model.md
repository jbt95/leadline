# Security model

- Parse-only: `leadline` reads source and coverage files and walks syntax trees. It never executes project code, test scripts, or build plugins.
- No network during analysis, coverage merge, or diffing, and no telemetry leaves the machine. The only fetching happens in the explicit `leadline update` command: it reads the latest release version and archive from GitHub (or `LEADLINE_BASE_URL`), verifies the archive against the release `SHA256SUMS`, and replaces the running binary. No other command touches the network, and nothing checks for updates automatically. When `LEADLINE_METRICS_DIR` is set, commands instead write an opt-in local metrics store (counters, per-operation durations, and gate finding counts; never source, paths, arguments, findings, or identities) into that directory — see [telemetry.md](telemetry.md).
- `git` is the only subprocess during analysis, invoked as `git` with fixed argument lists (`rev-parse`, `diff` with `--name-status -z` plus `-M` under `--renames` or `--no-renames` otherwise, `ls-files`, `ls-tree`, `cat-file --batch`, `show <rev>:<path>`, and one streamed `log --relative` history walk). Revisions starting with `-`, containing `:`, or containing control characters are rejected before execution. Outside analysis, only `leadline update` runs subprocesses — `curl`/`wget`, `sha256sum`/`shasum` (or PowerShell `Get-FileHash`), `tar`/PowerShell `Expand-Archive`, and the replaced binary's `--version` self-check — all with fixed argument lists, `stdin` closed, and no shell interpolation of user input (Windows uses one validated PowerShell `-Command` string). With `--integrations`, it also runs each detected harness's own updater (`pi update git:github.com/jbt95/leadline`, `omp plugin install git:github.com/jbt95/leadline --force`, `claude plugin update leadline@leadline`) with the same fixed-argument, stdin-closed rules; those tools may access their configured registries and run their normal package installation hooks, and a local OpenCode plugin path is never modified. `stats --open` is the only other subprocess: it launches the default browser at the served URL, best effort, and only when the flag is passed.
- MCP server is read-only with respect to the analyzed repository: its single `execute` tool returns analysis data only, with no shell access and no hook installation. The twenty analyzer tools are reachable only from inside the script sandbox, which has no filesystem, network, module, timer, or process access and is capped at 100 tool calls, 30 seconds, and 64 MB per run; a script cannot call them directly. The only writes are the opt-in local metrics store described above, which stays inside `LEADLINE_METRICS_DIR`; point that directory outside the repository to keep the repository itself write-free.
- `stats` is read-only with respect to the analyzed repository: it writes nothing, and its only subprocess is the existing Git adapter inside the analysis path. It binds `127.0.0.1` unless `--host` widens the bind, and the transport-level `Host` and `Origin` guards MCP uses apply unchanged — a loopback-bound listener answers only loopback authorities (`400` otherwise) and rejects a non-loopback browser origin with `403`. The embedded page makes no network calls and loads no CDN asset, `--open` launches the default browser only when the flag is passed, and serving adds no telemetry beyond the opt-in store described above.
- Coverage inputs (LCOV, JaCoCo XML) are data files parsed with a hardened XML reader; entity expansion and external references are not resolved.
- Reports contain function names, metrics, and line spans only. Source text is never embedded.
- Plan artifacts (`EXPLAIN` JSON) are untrusted data parsed under per-file, aggregate, depth, and count limits. `sql-plan` never connects to a database, executes SQL, or shells out to `psql`; MCP artifact arguments stay root-relative.
- Scanner SARIF is untrusted data parsed under per-file, aggregate, depth, and row limits. `security` never runs scanners, executes code, or touches the network; scanner messages and source text are dropped on read, and MCP artifact arguments stay root-relative.
- Scanner vulnerability reports (OSV, Trivy) are untrusted data parsed under per-file, aggregate, depth, row-count, and path-count limits. `vulnerabilities` never queries registries or package managers; finding descriptions and package-manager output are dropped on read, and MCP artifact arguments stay root-relative.
- SQL text (`.sql` files and host call sites) is parsed with a bounded tokenizer that retains shapes only. `sql` never executes SQL, connects to a database, or shells out to `psql`; findings carry rule IDs and remediations, never SQL text or literals; MCP artifact arguments stay root-relative.
- Secret gating delegates detection to an installed `gitleaks` binary: the only detector, always invoked with `--redact`. The shared runner uses private temporary files with cleanup traps, fixed argument vectors, and quoted paths; scanner output is suppressed and SARIF reports never print. A missing binary fails visibly, never silently.
